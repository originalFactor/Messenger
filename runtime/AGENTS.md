# runtime — companion shell-runtime app (`cc.ptoe.messenger.runtime`)

The agent-tool host and terminal UI for Android. Runs under its OWN UID with **targetSdk 28** (minSdk 28) so its process stays in the legacy `untrusted_app_27` SELinux domain.

## Why it exists (do not regress)

- Android 10+ SELinux W^X strips `execute`/`execute_no_trans` on `app_data_file` from the `untrusted_app` domain that targetSdk 29+ apps run in — the main app (targetSdk 36) can never exec binaries inside its data directory. The companion's deliberate targetSdk 28 keeps exec rights (verified on-device: the main app's domain gets `denied { execute_no_trans }`).
- **`sharedUserId` with the main app is BANNED**: PackageManager derives seInfo's targetSdk from the highest-targetSdk member at install time, so installing the companion after the main app silently pulls it into the modern domain (install-order dependent, silently broken). `run-as` tests are also misleading (`runas_app` retains exec rights).
- The deliberate targetSdk disables lint's `ExpiredTargetSdkVersion` fatal check in `runtime/build.gradle.kts` (else every `lintVital` fails).

## Design

- **Pinned Termux bootstrap**: per-build-type `ndk.abiFilters` (release `arm64-v8a`; debug `arm64-v8a` and `x86_64` for devices and AVDs) decide which bootstrap archives are downloaded and SHA-256-verified at build time into `jniLibs/<abi>/libbootstrap.zip.so` — only the archives of the ABIs actually being built are fetched — then `TermuxRuntime` extracts it atomically (staging + backup + version/ABI/hash marker; archive-path + symlink-graph validation in `RuntimePathPolicy` — symlink targets may be directories) into its OWN `files/agent-runtime/runtime-<abi>`.
- **Prefix rewriting**: the bootstrap bakes `/data/data/com.termux/files/usr` into its scripts; `patchTermuxPrefix` rewrites it to the extracted copy for `bin/`, `libexec/`, `lib/apt/methods/` (shebang-guarded) and `etc/`. Termux-app `etc/profile.d` hooks are dropped (`DROPPED_PROFILE_HOOKS` — they would run the second stage or fail on a foreign HOME). The install marker carries a `layout` generation (`LAYOUT_VERSION`) so old extractions are redone. `writePrefixOverrides` regenerates `etc/apt/apt.conf`, the CA bundle, and `etc/messenger.bashrc` on every ensure.
- **Workspace lives here too**: `files/agent-runtime/{runtime-<abi>,workspace}`. The main app cannot read another UID's files, so workspace file operations are brokered over AIDL.
- **Access control**: `ShellService` is protected by the signature-level `cc.ptoe.messenger.runtime.permission.SHELL` and every call re-checks it via `checkCallingPermission`.

## AIDL surface (`IShellService`/`IShellCallback`/`IMcpCallback`/`ToolResult`, copies duplicated in `androidApp`)

- The appended `trackedWorkspaceProtocol` / `trackedWorkspaceOperation` / `trackedWorkspaceStatus` are disabled: the version is 0, direct execution returns an error, and status is always unknown. The experimental journal is writable by shell and workspace operations running under the same Runtime UID, so it cannot establish trustworthy stop or at-most-once proof. File permissions and the signature-protected AIDL do not isolate same-UID processes. Do not enable the protocol until a separately protected authority can establish the full worker-stop guarantee, including subprocesses. Existing untracked AIDL methods remain available.
- `safeWorkspaceProtocol` / `safeWorkspaceGrep` expose a separate versioned synchronous capability for the Kotlin host. It executes only the immutable APK-installed `librg.so` with an empty environment, bounds output and runtime, drains stdout/stderr concurrently, and kills and joins the trusted process on timeout or any failure before returning. Messenger tracks this call in its own process; it must treat Binder death and lost connection as UNKNOWN. Do not execute the shell-writable ripgrep copy for this capability. Older companion versions do not expose it.
- `submit` / `cancel` — agent tool commands (per-request jobs; the binding must stay alive for the WHOLE request or the cached-app freezer can suspend the companion mid-work).
- `workspace{Glob,Grep,Read,Edit,Create}(root, …)` — synchronous, return a `ToolResult` Parcelable (`WorkspaceOps`). Every method takes a leading workspace `root`. An explicit non-blank root must be an existing directory or the call reports "unavailable"; null/blank uses the companion's own workspace. Project-bound callers must pass their actual root so an unavailable project cannot silently operate elsewhere.
- `temporaryChatWorkspace(conversationId)` creates a per-conversation directory under the Runtime cache, keyed by a hash of the ID. The main app passes that path to Core and to the Runtime tools, so both execute under the companion UID. Cached contents can be cleared by the OS.
- `startMcpProcess` / `sendMcpInput` / `stopMcpProcess` — stdio MCP for the main app's `McpManager`.
- MCP and ACP sessions use separate in-process generation-bound registries. A duplicate live or launching ID is rejected; old callbacks can affect only their own entry, and the ID remains reserved until launch, exit and admitted Binder callbacks finish. ACP protocol version 2 binds both input and stop to the callback Binder supplied at start, so stale requests cannot target a different callback's reused ID. An admitted input pins its generation until the write returns, even after child exit. Stop waits for a concurrent launch and direct-child close; `onDestroy` drains off the main thread and blocks new MCP/ACP admission across recreated service instances until successful completion. A failed or indefinitely stalled drain keeps admission closed for that process. A failed close keeps that ID unavailable. Complete stdin frames are serialized per session, but close kills the child before waiting for the writer. These guarantees track only the direct child and do not establish the platform fence required for Room cutover.
- MCP/ACP session stop kills and waits for the direct process before closing its stdin writer, allowing a full pipe write to finish. A failed or interrupted child wait must not emit an exit callback; its session remains unverified. A descendant may outlive the direct process; the callback is not proof that an arbitrary detached process tree has stopped.
- No session API: the terminal UI is in-process (see below).

## Terminal UI

- The companion IS the user-facing terminal: `TerminalActivity` (launcher, `singleTask`, `adjustResize`) hosts the vendored Termux `TerminalView` + `ExtraKeysBar` (Termux default extra-keys layout, one-shot CTRL/ALT) with a toolbar (title + keyboard/paste).
- Sessions run the bootstrap's `bin/bash` over a real PTY (`cpp/termux.c` JNI, `libtermux.so`, built per-ABI via NDK `30.0.16248370` + CMake `4.1.2`). The `externalNativeBuild` block is declared ONLY when `ext["buildRuntimeNative"]` is true (default; `-Pmessenger.buildRuntimeNative=false` disables it): AGP resolves the NDK while CONFIGURING any module that declares one, so an unconditional block made every `:desktopApp:*` build fail with "NDK not configured" on hosts that point `ANDROID_HOME` at an empty SDK (the Desktop CI jobs do exactly that). Spawned as argv `[<prefix>/bin/bash, --rcfile, <prefix>/etc/messenger.bashrc, -i]` — argv[0] MUST be the program name (the JNI hands the array to `execvp`; a leading `-` makes bash a login shell and dies with status 1). The generated rc replays Termux's login sequence against the extracted prefix. No policy filtering of user commands. Sessions die in `onDestroy`; tapping a finished session starts a new one.
- The main app opens it via `openRuntimeTerminal()` (explicit component intent); when the companion is absent the main app disables agent tools entirely (no fallback shell) and shows `terminal_not_installed`.

## Vendored Termux code (Apache-2.0, not GPL)

`src/main/java/com/termux/{terminal,view}` + `src/main/cpp/termux.c` are vendored from **termux-app v0.118.3** (`terminal-emulator` + `terminal-view` are Apache-2.0, exempt from upstream GPLv3; each file keeps its attribution header). Never copy `termux-shared` (that IS GPLv3). Only local change: the two `R` imports point at `cc.ptoe.messenger.runtime.R`. Re-vendoring = re-copy from the pinned tag + re-apply the R import + keep NDK/CMake flags in sync with `build.gradle.kts`.

## Other notes

- **ripgrep for the `grep` tool**: pre-built static binaries are committed as `src/main/jniLibs/<abi>/librg.so` (AGP strips them — `keepDebugSymbols += "**/librg.so"` keeps them byte-identical in the APK). `TermuxRuntime.ripgrepBinary` copies it to `<prefix>/bin/rg` (on PATH for terminal sessions too) without requiring the bootstrap install; `WorkspaceOps.grep` runs it with the workspace as cwd.
- AGP's `CANNOT_BUILD_SELECTED_TARGET_ABI` diagnostic is suppressed in `gradle.properties` Some native deps are ARM-only, while debug includes the `x86_64` emulator ABI; override debug with `-Pmessenger.debugAbis`, and release with `-Pmessenger.abis`.
- **Release build**: R8 + resource shrinking are ENABLED (`isMinifyEnabled = true`), with rules in `runtime/proguard-rules.pro`. The kept surface is the vendored Termux classes (one is inflated by FQN from `activity_terminal.xml`, and `libtermux.so` binds `Java_com_termux_terminal_JNI_*` by name), the AIDL stub/proxy/callback classes, `ToolResult`'s `CREATOR`, and the manifest-declared `TerminalActivity`/`ShellService`.
- Distribution: users install the matching-ABI runtime APK alongside the main APK; CI builds and attaches the `arm64-v8a` `runtime-release.apk` (no ABI splits, so no ABI suffix).

- `startAcpProcess` / `sendAcpInput` / `stopAcpProcess` provide a separate stdio process namespace for installed ACP Agents over the same signature-protected AIDL. ACP launches explicit argv in an existing absolute Runtime workspace. Its stdout carries ACP only, and the main app relays it to Core.
